# 模板分发与主题平台设计

## v0.4.0 已实现的边界

- 应用内置 Orbit、Chalk、Thesis、Brief 四套原创建议稿，每套七页，包含主题 CSS、示例 Markdown、备注和封面。
- 主题库支持搜索、分类、逐页预览、创建新文稿、给当前文稿换主题，以及导入/导出 `.marpora.json` 主题包。
- 导入包保存在本机 IndexedDB；普通 Markdown 的 `theme` 名称可以在重启后找到已安装 CSS。坏 CSS 会在安装前拒绝，损坏的历史记录会被隔离。
- 换主题是一次可撤销的文本事务，只编辑 YAML 标量范围；不把整份 YAML 或 Markdown 重新序列化。复杂、不明确的 YAML 需要用户在源码中修改。
- 不包含账号、在线商城、收款、创作者结算、远程自动安装或自动更新。现在下载 JSON 文件并通过应用显式导入。

## 仓库与托管

建议保留 `marpora/marpora` 作为应用仓库；应用二进制继续由 GitHub Releases 分发。新增主题已经放在独立 `templates/` 目录，可日后迁出，无需把应用代码搬走。

| 用途 | 建议位置 | 说明 |
| --- | --- | --- |
| 桌面应用源码 | `marpora/marpora` | 应用、渲染与安装包发布 |
| 免费主题源码 | 未来的 `marpora/themes` | CSS、起始文稿、封面、清单，PR 审核贡献 |
| 产品网站与主题展示 | 未来的 `marpora/website` | 产品介绍、主题预览、使用文档 |
| 免费可下载主题包 | 静态 HTTPS 目录 / CDN | 固定版本 URL、包大小、SHA-256 |
| 付费主题包 | 私有对象存储 | 服务端验证购买权限后发短期下载链接 |
| 作者、商品、订单和授权 | 服务端数据库 | 不放在公开 Git 仓库或桌面应用配置中 |

`npm run templates:catalog` 会输出可直接上传的 `dist-catalog/`：目录 JSON、四个固定版本主题包、封面、许可证。它是静态文件集合，不要求服务器运行 Node，也不绑定某一家云服务。

免费开源目录可以先使用 GitHub 仓库 / Releases。GitHub Pages 适合公开项目文档，但其使用限制明确排除了以促成商业交易为主要目的的站点，因此不要将未来的主题商城部署在那里。[GitHub Pages 使用限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

对于新产品网站和未来商城，建议使用 Cloudflare Workers Static Assets：先托管静态展示，真正需要订单接口时再加 Worker API。主题文件较少时静态资产即可；付费文件使用私有 R2，API 验证购买权限后生成短期下载 URL。[静态网站托管](https://developers.cloudflare.com/workers/static-assets/)、[R2 临时下载链接](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)

## 是否需要域名与新网站

技术上不需要先买域名才能分发模板。现在的应用、GitHub 下载和主题包导入可以独立工作。

如果打算长期经营，建议注册一个品牌主域名。以 `marpora.app` 作为命名示例，实际需确认可注册性和商标情况。一个网站就足够：根路径介绍产品，`/themes` 展示主题，`/docs` 放文档；以后需要时再加 `api.` 和 `downloads.` 子域名。无需为每套模板申请域名，也无需让桌面应用绑定一个商店账号才可离线使用。

网站代码独立仓库，免费主题独立仓库；付费包源码和交付文件保持私有。v0.4.0 不会创建网站、注册域名或开启付费云资源。

## 从精品主题到创作者分成

1. **先验证主题的价值。** 官方维护免费基础包，再发布少量完整的学术、技术或商务包；交付的不只是配色，还应包括标题、章节、图表、公式、对比、代码、引用、备注和使用指南。
2. **再做官方付费下载。** 展示页和结账由网站负责。服务端处理支付通知，幂等记录订单与授权；验证后给下载链接。应用只安装下载到的主题数据，不内置支付运行时。
3. **最后邀请第三方作者。** 增加作者审核、素材来源与许可记录、版本审核、收益台账、退款关联和结算规则。可评估 Stripe Connect 的 marketplace 流程，它支持平台收款并向卖方分配款项；是否适用还需根据实际经营主体、作者所在地及平台规则核对。[Stripe Connect](https://docs.stripe.com/connect)

先邀请少量作者比立刻开放自由上传更容易保证品质。CSS 和 Markdown 是离线可复制的交付物，商业价值应放在设计、配套版式、持续更新和清晰授权上，不宜依赖会破坏离线体验的强制联网 DRM。

## 目录协议与后续安装流程

`catalog.json` 记录 `schemaVersion`、发布者和每个包的 `id/version/minAppVersion`、分类、作者、许可、预览、下载路径、字节数和 SHA-256。包内容不可变，发布新版本使用新路径。不同来源不得抢占已安装的主题名称。

未来的远程目录应经过 HTTPS、来源信任和发布审核；哈希只是文件完整性校验，不等同于发布者签名。付费购买权与包下载地址分离，更新必须明确征得用户同意，避免悄悄改变已有演示稿。自动更新、版本共存和作者签名属于后续协议设计。

建议数据流：展示目录 → 查看实际渲染预览 → 下载或购买 → 服务端授权交付 → 本地校验安装 → 断网编辑、导出和演讲。
